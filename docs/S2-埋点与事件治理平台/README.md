## 深化方向速览（与 S1/S8 同模式）

| 方向 | 读者 | 核心场景 | 原型视图 |
|---|---|---|---|
| **方向 A · 事件字典与方案设计器（信息资产型）** | 数据治理 / 产品 | 事件是什么、方案怎么设计 | 字典首页 / 事件详情 / 方案列表 / **设计器** |
| **方向 B · 实时观测与验收（运营型）** | 开发 / QA | 事件在不在跑、跑得对不对 | 实时观测大盘 / 验收工作台 |

**核心亮点**：**埋点方案设计器**——把"设计埋点方案"从"填表"变成"拖拽 + 即时反馈"，并实时生成 5 端 SDK 代码（Web TS / 桌面 TS+Rust / 移动 Swift / 服务端 Go+Java+Python / Agent Python）。

## 关键能力速览

| 能力 | 落地形式 |
|---|---|
| 事件与属性在线注册 | `event-dict` 模块 + 命名规范自动校验 |
| 相似事件/属性查重 | Jaro-Winkler + Sentence-BERT + 属性 Jaccard |
| Schema 版本化与兼容性检测 | `schema-svc` 模块 + 语义化版本（major.minor.patch） |
| 公共属性组 | 5 个预置组（user / device / app / session / agent）+ 自定义扩展 |
| 埋点方案设计器 | 拖拽设计 + SDK 代码实时生成（5 端） |
| SDK 模板 | 5 端齐备：Web / 桌面 / 移动 / 服务端 / Agent |
| 端侧自检工具 | 浏览器扩展 + 桌面调试面板 + 移动调试面板 + 服务端 CLI + Agent 断言 |
| 实时上报流预览 | Kafka Consumer + WebSocket 推送（延迟 ≤ 3s） |
| 4 类自动验收 | 覆盖率 / 完整率 / 时序 / 对账（与 S8 联动） |
| 契约下发到 S3 | Kafka `s2.schema.published`（延迟 ≤ 30s） |
| 事件资产化进 S1 | Kafka `s2.event.published`（延迟 ≤ 5min） |
| 双端上报去重 | 主体端规则定义 + DWD 层去重（与 S5 协作） |

## 核心交付指标（SRS §1.4 / §9）

| 维度 | 目标 |
|---|---|
| 规范覆盖 | 埋点规范覆盖率 100%；新增埋点评审通过率 ≥ 95% |
| 准确性 | 核心指标准确率 ≥ 99.9%；埋点字段完整率 ≥ 99% |
| 接入效率 | 新增一个事件的接入成本 ≤ 0.5 人日；新增一个端到端需求 ≤ 1 人日 |
| 资产化 | 已发布事件 100% 自动资产化进入 S1 |
| 验收左移 | 埋点验收从"上线后 18 天"左移到"上线前 ≤ 2 工作日" |
| 字典健康度 | 相似事件查重触发率 100%；僵尸事件占比 ≤ 2% |
| 双端一致性 | 双端去重规则覆盖率 100%；主体事件优先规则执行率 100% |
| 自举治理 | S2 自身的关键链路 100% 埋点自监控 |

## 关键架构决策（SDD §14 ADR 摘要）

| ADR | 决策 |
|---|---|
| ADR-S2-01 | 事件命名采用 `object_verb` 形式（小写下划线） |
| ADR-S2-02 | 公共属性组采用 5 个预置 + 自定义扩展 |
| ADR-S2-03 | 双端上报主体端默认 server，可逐事件覆盖 |
| ADR-S2-04 | 破坏性 Schema 变更强制影响评估 |
| ADR-S2-05 | SDK 5 端统一 API 风格，模板由 DG 维护 |
| ADR-S2-06 | 契约下发走 Kafka，S3 主动重试对账 |
| ADR-S2-07 | 验收由 S8 算力承载，S2 只负责触发与结果回写 |
