3.1总体分层架构图

智能体数据治理系统（ADGS）采用 数据面 · 治理面 · 消费面 三平面架构。 数据流纵向贯穿数据面与消费面，管控流自治理面下发，回流流自数据面/消费面回传 —— 三者构成「下发—执行—回流—再治理」的闭环。

数据面 Data Plane 承载业务数据
数据的生产、加工与存储：从多端采集到管道加工，再到分层建模落存。
S3 采集接入网关 · S4 管道编排 · S5 数仓建模
治理面 Governance Plane 仅元数据与控制指令
横切管控全链路：定义规范与契约、稽核质量、解析血缘、保障安全、度量治理成效。
S1/S2/S6/S7/S8/S9/S11/S12/S14（9 个子系统）
消费面 Consumption Plane 派生与结果数据
数据价值的对外交付：服务化出口、场景化数据应用与业务场景消费。
S13 数据服务与数据集 · S10 Agent 评测与 Trace
数据流（实线）
数据源 → 采集 → 管道 → 分层存储 → 服务 → 应用，纵向贯穿数据面与消费面。
管控流（橙色虚线）
治理面 → 数据面/消费面，下发规范、契约、策略与卡点。
回流流（青色点线）
数据面/消费面 → 治理面，回流技术元数据、血缘、运行指标与访问行为。

读图提示　① 治理面在上方「俯瞰」全链路，所有管控箭头向下、回流箭头向上，二者在走廊中成对出现 —— 这正是「跨平面依赖必须双向成对」原则的落地点（如 S1↔S5、S8→S4 与 S3→S8）。 ② S9 协作与工作流引擎、S14 治理度量与运营中心在本图（3.1 分层视图）中没有跨平面连线，它们参与的是治理面内部闭环（S7→S8→S9→S14→S1），详见 3.3 子系统依赖关系。 ③ S1 元数据与资产中心是全局最强依赖：S2/S5/S6/S7/S11/S13 均以其为事实源，其可用性要求最高（NFR-05）。 ④ 消费面不得绕过治理面直接对外供数 —— S10 可从 S5 取数，但产出仍需回流至 S13 统一出口。
